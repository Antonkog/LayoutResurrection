# Layout Resurrection

> **Kiroween 2026 — Frankenstein category**

![Layout Resurrection concept art](Layout%20Resurrection_%20Neon%20UI%20Revival.png)

Layout Resurrection is an Android Studio plugin that brings back the **WYSIWYG drag-and-drop UI design workflow** — but for **Jetpack Compose**. It repurposes Android Studio's built-in XML Layout Editor as a visual designer that continuously generates a matching `@Composable` Kotlin file.

---

## How it works

1. Open any XML layout file in Android Studio's **Design** tab.
2. Drag, drop, and configure Views using the existing Palette, Component Tree, and Attributes panel — no new canvas needed.
3. The plugin reads the underlying XML and generates (or updates) a **separate `.kt` file** containing a ready-to-use `@Composable` function.
4. Drop the generated composable into your Compose app and run it.

**Source of truth:** the XML file.  
**Sync direction (MVP):** one-way — XML → Compose only.

---

## Demo story

```
drag a Button onto the canvas
    → XML updates
        → plugin generates MyScreenComposable.kt
            → Compose screen runs on device
```

---

## Supported widgets (MVP)

| XML View | Generated Compose |
|---|---|
| `LinearLayout` (vertical / horizontal) | `Column` / `Row` |
| `TextView` | `Text` |
| `Button` | `Button` + `Text` |

Unsupported widgets and attributes produce explicit diagnostics — nothing is silently dropped.

---

## Architecture

```
XML text
  └─► secure XML parser (no DTD / no network)
        └─► Layout IR  (pure Kotlin/JVM, no IDE dependency)
              └─► Compose code emitter
                    └─► generated .kt file  (under Kotlin source root)
```

Two Gradle modules keep concerns separated:

| Module | Responsibility |
|---|---|
| `converter/` | XML parser, layout IR, Compose emitter, diagnostics, unit tests. **No IDE SDK dependency.** |
| `plugin/` | IDE action, document listener, debounced auto-sync, safe file writes, user notifications. |

A `sample-app/` module (added after the plugin MVP) validates generated code in a real Compose host app.

## Generated file policy

Every generated file starts with a header:

```kotlin
// ⚡ Generated by Layout Resurrection — do not edit manually.
// Source: res/layout/my_screen.xml
// Re-generated on XML save. Hand-edits will be overwritten.
```

Files are written to the Kotlin source root, **not** `res/`. The plugin will not overwrite a file whose header has been removed (opt-out of auto-sync).

## Non-goals (MVP)

- Replacing or modifying Android Studio's design canvas
- Two-way sync (Compose → XML)
- Runtime AI / cloud API calls
- Pixel-perfect layout fidelity or arbitrary custom Views
